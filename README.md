# 프로젝트 소개
해당 서비스에서는 학과, 학년, 관심분야, 거주 방식에 따라서 대학 공지 사항 리스트의 필터링과 현재 공지시항에 기반한 내용 요약 기능을 제공한다.

이를 통해 학생 개인에 맞춰진 현재 대학 상황과 참여할 수 있는 활동, 확인해야 하는 중요 내용을 열람하는 데 난이도를 낮출 수 있게 한다. 

또한 해당 요약의 근거가 되는 공지사항 페이지 리스트와 체크박스 기능을 저장함으로써 사용자가 지정한 중요 정보에 대한 접근과 공지시항에서 언급된 이벤트 참여 여부 확인을 용이하게 한다.

# 사용 리소스
- **Frontend**: React (모바일/웹 프로토타입)
- **Backend**: FastAPI (Python 기반 - AI 모델/크롤러 연동에 용이)
- **Database**: Firebase / Supabase (빠른 프로토타입 구축용)
- **AI/LLM**: OpenAI API

원문이 수정되면 공지 본문을 갱신하고 요약에도 반영한다.

# 원천 데이터 및 연계 방법

프로토타입 단계에서는 대학 시스템과의 direct API 연동이 어려울 수 있으므로, 웹 크롤링(Web Scraping)과 **파이프라인 구축** 중심의 연계 방안이 유력하게 사용될 수 있다.

## 대상 원천 데이터 (Source Data)

- **대학 메인 홈페이지 공지사항**: 학사, 장학, 행사, 일반공지.
- **단과대/학과별 홈페이지 게시판**: 학과 전공 관련 특화 공지, 세미나, 학과 전용 장학.
- **학생복지/주거 관련 게시판**: 기숙사 홈페이지 공지, 학생회/동아리 연합회 공지.
- **외부 지자체/청년 정책 공지 (선택적)**: 대학 인근 지자체의 청년 주거·생활 지원 공지.

## 데이터 연계 및 처리 파이프라인 (Data Pipeline)

1. **데이터 수집 (Scraping)**
    - **도구**: Python (`BeautifulSoup`, `Playwright`, `Scrapy`).
    - **방식**: 주기적(예: 매시간 또는 매일 아침) 배치 작업을 통해 각 게시판의 신규 글 제목, 본문, 작성일, 첨부파일 유무, 원본 URL 수집.
2. **데이터 전처리 (Preprocessing)**
    - HTML 태그 제거, 텍스트 정문화, 중복 공지 제거.
3. **AI 파이프라인 연계 (LLM Processing)**
    - **요약 및 추출**: OpenAI API (GPT-4o-mini), Anthropic Claude API, 혹은 파인튜닝된 소형 LLM 활용.
    - **Prompt**: 본문 입력 ➔ ① 3줄 핵심 요약, ② 핵심 분류 카테고리/태그 추출, ③ 주요 일정/액션 아이템 추출.
4. **데이터베이스 저장 & 백엔드 연계**
    - **DB (e.g., PostgreSQL / Firebase)**: 파싱된 공지 데이터 + AI 요약문 + 사용자 프로필 데이터 저장.
    - **검색/필터링**: 메인 서비스 백엔드(Node.js, FastAPI 등)에서 사용자 설정값에 맞춰 DB 조회 결과를 프론트엔드로 전달.

# 기능 검증 테스트 계획
| 테스트 대상 | 확인 항목 및 정상 동작 기준 |
| --- | --- |
| 공지 수집 및 저장  | 동일한 공지가 중복으로 수집되거나 저장되지 않는다. |
| 공지 갱신 | 변경된 원문이 공지 본문과 요약에 모두 반영된다. |
| 사용자 조건 설정  | 사용자 정보를 변경하면 해당 조건에 맞게 공지 목록이 갱신된다. |
| 공지 분류 | 설정한 조건에 맞는 공지가 표시된다. |
| 공지 목록 제공 | 게시일 기준 최신순으로 표시된다. 공통 공지는 모든 사용자에게 제공되며, 필요한 공지가 누락되지 않는다. |
| 공지 요약 | 요약이 원문의 내용을 정확하게 전달한다. 사용자가 요약만 읽고도 공지의 핵심을 이해할 수 있다. |
